### 七、时钟源相关备忘

48. CSR time (0xc01) 返回 `insn_counter`（riscv_cpu.c 第 745 行）
49. `rtc_get_time()` 在 `!rtc_real_time` 模式下返回 `insn_counter / RTC_FREQ_DIV`（RTC_FREQ_DIV=16）
50. FDT 声明 `timebase-frequency = 10000000`（10MHz）
51. 原版 TinyEMU 的 `RTC_FREQ_DIV = 16`，含义是 "CPU 频率 = RTC_FREQ × 16 = 160MHz"，即每 16 条指令 mtime 加 1
52. `riscv_cpu_get_cycles()` 返回 `s->insn_counter`（已确认，riscv_cpu.c 第 1328 行）
53. **时钟不一致问题**：CSR time 返回 `insn_counter`（原始值），但 CLINT mtime MMIO 读返回 `insn_counter / 16`。内核读 CSR time 和读 CLINT mtime 会得到不同的值。OpenSBI 写 timecmp 基于 CLINT mtime（除以 16 后的值），而 template.h 的 inline check 比较的是 `insn_counter / 16 >= *timecmp_ptr`，这条路径是一致的

### 八、CLINT / timer 机制备忘

54. 正确的 timer 调用链（已验证打通）：内核 SBI ecall 设 timecmp → OpenSBI 写 CLINT mtimecmp → mtime >= mtimecmp 时 CLINT 触发 M-mode timer 中断 → OpenSBI 捕获 → `sbi_trap_nonaia_irq(7)` → `sbi_timer_process()` → `csr_set(CSR_MIP, MIP_STIP)` → 内核收到 S-mode timer 中断
55. TinyEMU CLINT FDT 只声明了 M-mode 中断（IRQ 3 和 IRQ 7），在 SBI 委托模型中这是正确的
56. TinyEMU 没有内嵌 SBI 实现，ecall 由 OpenSBI 固件在 M-mode 处理
57. CLINT MMIO 写 timecmp 时会 `riscv_cpu_reset_mip(MIP_MTIP)` 清除 timer pending
