### 七、时钟源现状（关键修正）

43. CSR time (0xc01) 返回 `insn_counter`

### 八、CLINT / timer 机制备忘

50. timer 调用链：内核 SBI ecall → OpenSBI 写 CLINT mtimecmp → `insn_counter >= timecmp` 时 set MIP_MTIP → OpenSBI 捕获 → `sbi_timer_process()` → set MIP_STIP → 内核收到 S-mode timer 中断
51. CLINT MMIO 写 timecmp 时会 `riscv_cpu_reset_mip(MIP_MTIP)` 清除 timer pending
52. TinyEMU 没有内嵌 SBI 实现，ecall 由 OpenSBI 固件在 M-mode 处理

### 九、Console 通路

53. HTIF 输出：内核 → SBI ecall → OpenSBI → HTIF → TinyEMU → Godot
54. HTIF 输入：Godot → TinyEMU `htif_poll()` → HTIF → OpenSBI → 内核 `hvc_riscv_sbi` → TTY
55. `hvc_riscv_sbi` 输入是轮询机制
56. virtio console 设备同时存在，`CONFIG_VIRTIO_CONSOLE=y`

### 十一-A、128KB 边界的两个巧合（v11 新增）

69. **glibc `DEFAULT_MMAP_THRESHOLD = 128 * 1024`**（glibc malloc/malloc.c:946）— malloc >= 128KB 时从 brk 切换到 mmap 分配。这意味着 `malloc(131072)` 会调用 `mmap(MAP_ANONYMOUS)` 而不是 `brk`
70. **Linux 6.12 `VM_READAHEAD_PAGES = SZ_128K / PAGE_SIZE = 32`**（include/linux/pagemap.h:1365）— 默认 readahead 窗口恰好 128KB。read() > 128KB 时需要第二轮 readahead
71. ~~两个 128KB 阈值可能都参与了问题，但 #67（纯内存也卡）说明 mmap 路径是主要嫌疑~~ → **v12 已排除**：brk 和 mmap 都卡，问题不在分配方式

### 十一-B、TinyEMU sfence.vma / TLB 实现细节（v11 新增）

72. **`sfence.vma` 完全忽略 rs2（ASID 参数）**（riscv_cpu_template.h:1332-1342）— 只检查 rs1
73. **`tlb_flush_vaddr()` 是空壳**：直接调用 `tlb_flush_all()`（riscv_cpu.c:603-606）— 所有 sfence.vma 都变成全量 flush
74. **TLB 无 ASID 字段**：`TLBEntry` 只有 `{vaddr, mem_addend}`（riscv_cpu_priv.h:173-176），satp 写入时注释 `/* no ASID implemented */`（riscv_cpu.c:952）
75. `set_mstatus()` 在 SUM/MXR/MPRV 位变化时正确调用 `tlb_flush_all()`（riscv_cpu.c:680-682）
76. 以上 sfence.vma 问题只影响性能（过度 flush），不影响正确性 — **不是卡死的根因**

### 十一-C、Linux 6.12 uaccess.S 分析（v11 新增）

77. `__asm_copy_to_user` 使用 `csrs CSR_STATUS, SR_SUM` 开启 S-mode 用户页面访问，完成后 `csrc` 关闭（arch/riscv/lib/uaccess.S）
78. 每次 `copy_to_user` 调用触发 2 次 `set_mstatus` → 2 次 `tlb_flush_all`（SUM 位变化）
79. `CONFIG_RISCV_ISA_V` 未启用，不会走 vector usercopy 路径
80. `CONFIG_RISCV_ALTERNATIVE=y` 已启用，但 `mvendorid=0` 不会触发 SiFive errata patch

82. virtio-blk 请求在 `queue_notify` 中同步处理完毕，`set_irq` 立即触发 PLIC 中断

### 十一-E、wfi 不会永久卡死的保障（v11 新增）

### 十六、rootfs 镜像修改方法（无需 sudo/mount）

用 `debugfs` 直接操作 ext2 镜像，不需要 mount 也不需要 root 权限：

```bash
ROOTFS=/mnt/e/development/JediTerm-Godot/addons/jediterm/native/tinyemu/images/python/root-py312-riscv64.bin

# 写入文件
debugfs -w -R "write /tmp/test_foo /root/test_foo" "$ROOTFS"

# 设置可执行权限（0100755 = -rwxr-xr-x）
debugfs -w -R "set_inode_field /root/test_foo mode 0100755" "$ROOTFS"

# 查看目录内容
debugfs -R "ls /root/" "$ROOTFS"

# 读取文件到本地
debugfs -R "dump /root/test_foo /tmp/test_foo_copy" "$ROOTFS"

# 删除文件
debugfs -w -R "rm /root/test_foo" "$ROOTFS"
```

镜像路径在 WSL2 中是 `/mnt/e/...`，修改后 Godot 直接能用（同一个文件）。
