## 已确认事实清单（TinyEMU + Linux 6.12 启动调试）

### 一、硬件/平台层（TinyEMU 模拟器）

1. TinyEMU 的 ISA：`rv64imafdc`，不支持 Zba/Zbb/Zbc/V 等新扩展
2. RAM 起始地址：`0x80000000`
3. HTIF MMIO 基地址：`0x40008000`，布局：offset 0 = tohost，offset 8 = fromhost
4. CLINT 地址：`0x02000000`，PLIC 地址：`0x40100000` — 与 OpenSBI generic 平台天然匹配
5. 串口输出唯一通道：HTIF（`compatible = "ucb,htif0"`），没有 ns16550 / sifive-uart
6. TinyEMU 创建了 virtio console 设备（`virtio_console_init(vbus, p->console)`）

### 二、OpenSBI 层（v1.6，Buildroot 编译）

7. OpenSBI generic 平台已编译 HTIF 串口驱动（`fdt_serial_htif.c` 在 carray 中）
8. OpenSBI banner 能完整输出 — HTIF 通路正常
9. `Platform Console Device: htif` — OpenSBI 正确识别了 HTIF
10. fw_payload 模式可用（OpenSBI + 内核打包为一个 `fw_payload.bin`，当 bios 加载）
11. OpenSBI 的 HTIF FDT 约定：reg[0] = fromhost 地址，reg[1] = tohost 地址（与直觉相反）
12. 当前 FDT 中 htif 节点的 reg 值是正确的：`reg[0]=0x40008008`(fromhost), `reg[1]=0x40008000`(tohost)

### 三、TinyEMU C 代码已做的修复（riscv_machine.c / riscv_cpu.c）

13. FDT chosen 节点已加 `stdout-path = "/htif"` — OpenSBI 需要它来找到输出设备
14. FDT htif 节点已加 `reg` 属性（两组地址，各 8 字节）— OpenSBI 需要它来读写 HTIF MMIO
15. `htif_handle_cmd()` 的 else 分支已加 `s->htif_tohost = 0` — 防止未知命令卡死 OpenSBI
16. CSR `0xf11`(mvendorid)、`0xf12`(marchid)、`0xf13`(mimpid) 已补实现，返回 0
17. 约 40 个其他 CSR（PMU 计数器 0xb03-0xb1f、pmcounteren 0x320、menvcfg 0x30a 等）已补为返回 0
18. `COUNTEREN_MASK` 已从 `(1<<0)|(1<<2)` 改为 `(1<<0)|(1<<1)|(1<<2)` — 加了 TM 位，允许 S-mode 读 time CSR

### 四、TinyEMU C++ 代码已做的修复（tinyemu_vm.cpp / tinyemu_vm.h）

19. `CharacterDevice` 已从栈上局部变量提升为类成员 `_console_dev_storage` — 修复悬空指针 bug
20. FDT bootargs（C++ 侧）设为 `"earlycon=sbi console=hvc0 root=/dev/vda rw"` — 但被内核 CMDLINE_FORCE 忽略（见 #24）

### 五、内核层（Linux 6.12.20，Buildroot 编译）

21. 内核确实在运行 — exception trace 显示 ecall(cause=0x9) 和 timer 中断(cause=0x80000007)
22. `CONFIG_HVC_RISCV_SBI=y` 已加入并确认编译成功（`hvc_riscv_sbi.o` 出现在编译日志中）
23. `CONFIG_SERIAL_EARLYCON_RISCV_SBI=y` 已有，earlycon 驱动源码存在（`EARLYCON_DECLARE(sbi, early_sbi_setup)`）
24. **`CONFIG_CMDLINE="earlycon=sbi console=hvc0 root=/dev/vda rw"` + `CONFIG_CMDLINE_FORCE=y`** — 已修复，加入了 `earlycon=sbi`
25. `CONFIG_VIRTIO_CONSOLE=y`、`CONFIG_VIRTIO_BLK=y`、`CONFIG_VIRTIO_NET=y` 已有
26. 内核使用 Buildroot 的 `qemu_riscv64_virt_defconfig` 为基础（非精简 defconfig）

### 六、HVC 设备竞争（待验证）

27. `hvc_riscv_sbi` 注册为 vtermno=0，即 hvc0（`hvc_alloc(0, 0, &hvc_sbi_v01_ops, 256)`）
28. `virtio_console` 的 vtermno 是动态分配的（`hvc_alloc(port->cons.vtermno, ...)`），具体编号取决于初始化顺序
29. 两者可能竞争 hvc0 — 如果 virtio console 先注册拿到 hvc0，则 `console=hvc0` 的输出走 virtio 通路而非 SBI → HTIF 通路。**尚未验证实际注册顺序。**

### 七、已解决的问题

30. ~~OpenSBI banner 正常输出后，内核无任何文字输出~~ — **已解决**：根因是 `CONFIG_CMDLINE_FORCE=y` 且 CMDLINE 中缺少 `earlycon=sbi`，加入后内核早期输出恢复正常
31. earlycon=sbi 通路已打通：内核 → SBI ecall → OpenSBI → HTIF → TinyEMU 输出
