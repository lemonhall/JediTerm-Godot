### 六、已解决的问题

32. ~~OpenSBI banner 正常输出后，内核无任何文字输出~~ — 已解决：根因是 `CONFIG_CMDLINE_FORCE=y` 且 CMDLINE 中缺少 `earlycon=sbi`，加入后内核早期输出恢复正常
33. earlycon=sbi 通路已打通：内核 → SBI ecall → OpenSBI → HTIF → TinyEMU 输出
34. ~~内核卡在 `time_init()` / `cpuhp_setup_state()` 不返回~~ — 已解决：根因是 `riscv_machine_get_sleep_duration()` 中 `timecmp = U64_MAX` 时 int64 溢出导致 MIP_MTIP 被错误 set，形成 M-mode timer 中断风暴，CPU 被淹没无法推进。修复为 uint64 无符号比较后，timer 初始化正常通过，initcall 序列恢复推进。
35. ~~内核卡在 `check_unaligned_access_all_cpus`~~ — 已解决（绕过）：根因是 S-mode timer 中断未到达内核导致 jiffies 不递增。将内核配置改为 `CONFIG_RISCV_EMULATED_UNALIGNED_ACCESS=y` 跳过了 jiffies 计时循环。
36. ~~内核卡在 EXT4 rootfs 挂载~~ — 已解决：根因同 #37
37. ~~S-mode timer 中断未到达内核~~ — **已解决**：根因是 CSR `0xfb0` 被错误地作为 "vendor ID" stub 返回 0，但 `0xfb0` 实际是 `CSR_MTOPI`（AIA 高级中断架构的 M-mode Top Interrupt CSR）。OpenSBI 探测时读到无 trap，误判为 SMAIA 存在，导致 timer 中断走了 `sbi_trap_aia_irq()` 路径而非 `sbi_trap_nonaia_irq()` 路径，`sbi_timer_process()` 从未被调用，`MIP_STIP` 从未被 set。从 stub 列表删除 `0xfb0` 后，OpenSBI 正确判定 SMAIA 不存在，走 nonaia 路径，timer 中断链路完全打通。
38. 同时从 stub 列表删除的危险 CSR：`0x14d`(stimecmp/SSTC)、`0x30a`(menvcfg)、`0x30c`(mstateen0)、`0x7a0`(tselect)、`0x7a1`(tdata1)、`0x7a4`(tinfo)、`0xda0`(scountovf)、`0xfb0`(mtopi/SMAIA) — 这些 CSR 被 OpenSBI 用于运行时探测扩展支持，stub 返回 0 会导致误判
39. ~~输入 root 后虚拟机重启~~ — **大概率已解决**：关闭 virtio-net 后不再复现。根因推测为 virtio-net TX timeout watchdog 触发内核 panic 或 SBI system_reset

### 七、时钟源相关备忘

40. CSR time (0xc01) 返回 `insn_counter`（riscv_cpu.c 第 745 行）
41. `rtc_get_time()` 在 `!rtc_real_time` 模式下返回 `riscv_cpu_get_cycles()`，已去掉 `/ RTC_FREQ_DIV`
42. FDT 声明 `timebase-frequency = 10000000`（10MHz），但实际 CSR time 以 `insn_counter` 速率递增，两者是否匹配取决于每秒执行多少条指令
43. 原版 TinyEMU 的 `RTC_FREQ_DIV = 16`，含义是 "CPU 频率 = RTC_FREQ × 16 = 160MHz"，即每 16 条指令 mtime 加 1。去掉除法后变成每条指令 mtime 加 1
44. `riscv_cpu_get_cycles()` 返回值是否等于 `insn_counter` 尚未最终确认

### 九、CLINT / timer 机制备忘

52. 正确的 timer 调用链（已验证打通）：内核 SBI ecall 设 timecmp → OpenSBI 写 CLINT mtimecmp → mtime >= mtimecmp 时 CLINT 触发 M-mode timer 中断 → OpenSBI 捕获 → `sbi_trap_nonaia_irq(7)` → `sbi_timer_process()` → `csr_set(CSR_MIP, MIP_STIP)` → 内核收到 S-mode timer 中断
53. TinyEMU CLINT FDT 只声明了 M-mode 中断（IRQ 3 和 IRQ 7），在 SBI 委托模型中这是正确的
54. TinyEMU 没有内嵌 SBI 实现，ecall 由 OpenSBI 固件在 M-mode 处理
55. CLINT MMIO 写 timecmp 时会 `riscv_cpu_reset_mip(MIP_MTIP)` 清除 timer pending
