### 二十、MSVC slirp 网络修复（v18 新增）

113. **★ slirp 网络已通！ping 网关 10.0.2.2 成功，可访问外网**
114. **根因：MSVC `u_int` 位域分配 4 字节，导致 IP 头解析全部错位**
    - `struct ip` 的 `u_int ip_hl:4, ip_v:4` 在 GCC 下只占 1 字节（`__attribute__((packed))` 生效）
    - MSVC 忽略 `__attribute__((packed))`，且 `#pragma pack(1)` 不改变位域分配单元大小
    - `u_int`（4 字节）位域即使只用 8 bit，MSVC 仍分配 4 字节，后续字段全部偏移 3 字节
    - 日志证据：`ip_input: v=4 hl=5`（正确）但 `proto=0 src=ffffffff dst=00440043 len=0`（全错）
115. **修复方案：MSVC 下将位域类型从 `u_int` 改为 `uint8_t`**
    - `slirp/ip.h` — `struct ip`：`uint8_t ip_hl:4, ip_v:4`（`#ifdef _MSC_VER`）
    - `slirp/ip.h` — `struct ip_timestamp`：`uint8_t ipt_flg:4, ipt_oflw:4`
    - `slirp/tcp.h` — `struct tcphdr`：`uint8_t th_x2:4, th_off:4`
    - 同时保留 `#pragma pack(push, 1)` / `#pragma pack(pop)` 确保非位域成员也紧凑排列
116. **`#pragma pack(push, 1)` 已添加到**：
    - `slirp/ip.h`（文件级）
    - `slirp/tcp.h`（文件级）

### 十六、rootfs 镜像修改方法（无需 sudo/mount）

用 `debugfs` 直接操作 ext2 镜像，不需要 mount 也不需要 root 权限：

```bash
# ⚠️ 注意：从 Windows Git Bash / Claude Code 调用 WSL 时，必须用以下方式避免路径被 Git Bash 篡改：
# 正确：/c/Windows/System32/wsl.exe bash -c '...'
# 错误：wsl bash -c '...'  （Git Bash 会把路径转成 C:/Program Files/Git/...）
# 错误：wsl -- bash -c "...$HOME..."  （$HOME 会被 Windows shell 展开为 Windows 路径）

# debugfs 的路径必须内联写死，不能用变量（shell 转义问题）：
# 正确：debugfs -w -R "write /tmp/foo /root/foo" /mnt/e/.../root-py312-riscv64.bin
# 错误：debugfs -w -R "write /tmp/foo /root/foo" "$ROOTFS"  （变量展开可能出错）

ROOTFS=/mnt/e/development/JediTerm-Godot/addons/jediterm/native/tinyemu/images/python/root-py312-riscv64.bin

# 写入文件
debugfs -w -R "write /tmp/test_foo /root/test_foo" "$ROOTFS"

# 设置可执行权限（0100755 = -rwxr-xr-x）
debugfs -w -R "set_inode_field /root/test_foo mode 0100755" "$ROOTFS"

# 查看目录内容
debugfs -R "ls /root/" "$ROOTFS"

# 读取文件到本地
debugfs -R "dump /root/test_foo /tmp/test_foo_copy" "$ROOTFS"

# 删除文件
debugfs -w -R "rm /root/test_foo" "$ROOTFS"
```

镜像路径在 WSL2 中是 `/mnt/e/...`，修改后 Godot 直接能用（同一个文件）。

### 十七-A、从 Claude Code (Windows) 调用 WSL 的正确姿势（v13 新增）

```bash
# ✅ 正确方式：用 /c/Windows/System32/wsl.exe 绕过 Git Bash 路径篡改
/c/Windows/System32/wsl.exe bash -c 'export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin; 你的命令'

# ✅ 用单引号包裹 bash -c 的内容，防止 $HOME 等变量被 Windows shell 展开
/c/Windows/System32/wsl.exe bash -c '直接写 /home/lemonhall/... 而不是 $HOME/...'

# ❌ 错误：用 wsl 直接调用（Git Bash 会劫持路径）
wsl bash -c "..."  # → 路径变成 C:/Program Files/Git/...

# ❌ 错误：用 wsl -- bash -c（$HOME 被 Windows 展开）
wsl -- bash -c "echo $HOME"  # → /c/Users/lemon 而不是 /home/lemonhall

# ❌ 错误：在 bash -c 双引号内用 \$VAR（转义不稳定）
wsl -- bash -c "OBJDUMP=\$HOME/...; \$OBJDUMP -d ..."  # → 经常失败

# 系统的 objdump/readelf 不认 RISC-V，必须用 Buildroot 交叉工具链的版本
```
